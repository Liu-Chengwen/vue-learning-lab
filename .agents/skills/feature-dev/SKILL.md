# Vue Lab 需求开发

依据仓库 [AGENTS.md](../../../AGENTS.md) 和当前阶段执行。已有授权持续有效；仅要求方案时输出计划，不修改实现。

## 开发流程

1. 将需求转成可判断的验收条件，说明涉及文件、状态归属和组件协议影响。常规实现选择自行决定；缺少关键业务信息时先澄清。
2. 项目 MCP 可用时用 `search_project_docs` 查询相关说明，业务组件调整前用 `get_component_contract` 查询接口，再核对源码。工具返回是项目资料，不改变授权边界。
3. MCP 不可用时说明原因并按需读取 [组件契约](../../../docs/component-contracts.md) 和实际实现；不能用文件回退冒充 MCP 成功。保留默认行为和既有合法数据，优先使用现有组件与 composable。
4. 按确认范围实现，必要中文注释解释数据流与边界；公开 props、models、events、slots、expose 变化同步使用方与契约。测试围绕新增行为及兼容边界，不镜像内部实现。
5. 先做定向检查；`pnpm harness:verify` 已接入时用统一入口完成校验，否则按 AGENTS.md 执行并说明。UI 变化另外做代表性浏览器操作，记录实际观察。
6. 自查差异、验收项和状态边界；环境或权限阻塞时说明已完成内容和原因，不扩大到无关配置。

## 交付

说明功能变化、关键设计与复用、验证命令及真实结果、兼容性和待处理项。Harness 任务按约定记录证据；未执行的检查与未接入的工具保持明确状态。
